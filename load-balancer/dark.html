01

Satu alamat, satu pintu.

Client mengakses satu alamat publik. Load balancer menerima request dan menjadi perantara ke kumpulan server di belakangnya.

02

Pilih server yang tepat.

Algoritma menentukan server sehat yang menerima request. Coba bandingkan giliran merata dengan jumlah koneksi aktif paling sedikit.

03

Kembalikan jawabannya.

Server memproses pekerjaan, lalu response kembali lewat load balancer ke client. Client tidak perlu mengetahui server mana yang dipilih.

Model pembelajaran: satu request per koneksi, tanpa antrean kapasitas atau retry otomatis. Deteksi health dibuat instan dan durasi proses diperlambat agar alurnya terbaca; server B sengaja lebih lambat. Sistem produksi dapat memakai health check berkala, koneksi persisten, timeout, retry, dan beberapa load balancer untuk menghindari satu titik kegagalan.
